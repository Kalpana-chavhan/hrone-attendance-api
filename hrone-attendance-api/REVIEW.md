# REVIEW.md

Review of the starter `app/main.py`. The input-based examples (rows 1-4, 7, 9-12, 14, 16, 17) were run against the starter. The concurrency and database-down rows (6, 8, 13, 18) follow directly from the code: a check-then-insert with no unique index, and no ping or error handling.

| # | Where (function / line) | What is wrong | How you'd notice it | How I fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (l.34-35) | `punch_in.replace(hour, minute)` applies the shift start to the punch's own clock/date, not to the IST attendance date. Wrong when the server is not on IST, and impossible for overnight shifts. | Shift 09:30, punch 09:40:01 IST (= 04:10:01 UTC) returns 0 instead of 10. | Build the shift start as an IST datetime for the attendance date (`shift_bounds`) and subtract. |
| 2 | `compute_late_minutes` (l.36-37) | Floors to whole minutes first, then tests `> 10`. Anything from 10:01 to 10:59 after the start floors to 10 and is treated as on time; the rule is "strictly more than 10:00". | 09:40:30 returns 0, expected 10. | Compare whole seconds: late only when `seconds > 600`, then `seconds // 60`. |
| 3 | `compute_work_hours` (l.41) | Python `round()` on a float is banker's rounding on an inexact binary value, not half-up (R4). Instants are also not truncated to whole seconds. | 16218 s (4.505 h) returns 4.5, expected 4.51; 450 s returns 0.12, expected 0.13. | Integer maths on whole seconds: hundredths = `(seconds + 18) // 36`, no floats involved. |
| 4 | `compute_overtime` (l.46-47) | Four problems: no 30-minute minimum (R3); shift end is always on the punch date, so overnight shifts are wrong; `int()` instead of an explicit floor; subtracting an aware `end` from the naive datetimes PyMongo returns raises `TypeError`. | 10 minutes after shift end returns 10, expected 0. Overnight 22:00-06:00 with punch-out 06:40 next day returns 1480, expected 40. Naive `punch_out` gives `TypeError` (a 500). | End is built from the attendance date plus one day for overnight shifts; floor division; counted only when `>= 30`; client is `tz_aware` so everything is aware UTC. |
| 5 | `MongoClient(...)` (l.22) and every `datetime.now()` / `fromtimestamp()` | Naive datetimes everywhere: `datetime.now()` and `fromtimestamp(ms/1000)` use the server's local zone and are stored as if they were UTC. Results change with the server's time zone. | Same request gives different stored instants on a UTC server and an IST server. | `MongoClient(tz_aware=True, tzinfo=UTC)`, all instants are aware UTC, converted to epoch ms only at the API boundary (`ms_to_dt` / `dt_to_ms`). |
| 6 | `health` (l.72-74) | Always returns 200, even when MongoDB is down, so the runner would start testing a dead service. | Stop MongoDB: `/health` still says ok. | Pings MongoDB and returns 503 on failure. |
| 7 | `EmployeeIn` (l.53-60) | No validation at all. | `POST /employees` with `emp_code: "whatever"`, empty name, `email: "x"`, `shift_start: "99:99"`, `joined_on: "not-a-date"` returns 201. `shift_start == shift_end` is accepted. | Pattern/length constraints from the contract, real-date check for `joined_on`, and a model validator for `shift_start != shift_end`. |
| 8 | `create_employee` (l.79-83) | Check-then-insert with no unique index: two parallel creates both pass the check. Also `created_at` is naive local time and is returned as an ISO string instead of epoch ms. | Fire two identical POSTs at once: two 201s and a duplicate `emp_code`. `created_at` comes back as `"2026-10-10T07:23:39.2"`. | Unique index on `emp_code`; `insert_one` and catch `DuplicateKeyError` -> 409. `created_at` is UTC and serialised as epoch ms. |
| 9 | `list_employees` (l.93-96) | `skip = page * page_size` is off by one (page 1 skips the first page); `total` counts the whole collection, ignoring the department filter; no sort, so order is not by `emp_code`; `page` / `page_size` are not validated. | `page=1&page_size=2` returns EMP0002, EMP0003. `department=B` (2 people) reports `total: 6`. `page=0` and `page_size=-1` return 200. | `skip = (page - 1) * page_size`, `count_documents(filter)`, sort by `emp_code`, `page >= 1` and `1 <= page_size <= 100` (422 otherwise). |
| 10 | `punch_in` (l.101-113) | Unknown employee: `emp` is `None`, then `emp["shift_start"]` raises `TypeError`. | `POST /attendance/punch-in` for an unknown `emp_code` returns 500, expected 404. | `get_employee_or_404`. |
| 11 | `punch_in` (l.102-103) | The date is the server-local date of a naive timestamp, not the IST date (R1); overnight shifts are ignored; no truncation to whole seconds; `if body.punched_at` treats `0` as "not given". | A punch at 00:30 IST on the 6th gets date 2026-07-05 on a UTC server. `punched_at: 0` is stored as "now". | `attendance_date()` implements R1 incl. overnight; `instant_from_ms` truncates to seconds and only `None` means "now". |
| 12 | `PunchInIn` (l.63-66) | `punched_at: Optional[int]` is lax: integral floats and numeric strings are coerced and seconds-looking values pass. `status` is a free string. | `status: "NONSENSE"` returns 201 and is stored. Seconds-looking and string timestamps are accepted. | `EpochMs` = strict int in `[1e11, 4.1e12]`; `status` is a `Literal` of PRESENT / WFH / ON_DUTY. All give 422. |
| 13 | `punch_in` (l.104-118) | Check-then-insert race again, and there is no unique `(emp_code, date)` index. | Two simultaneous punch-ins both get 201 and two documents exist for the same day. | Unique index on `(emp_code, date)`; insert only; `DuplicateKeyError` -> 409. |
| 14 | `punch_in` response (l.119-121) | Leaks `id` (the `_id`), which must never appear, and returns `punch_in` as a datetime/ISO string instead of epoch ms. | Response has `"id": "6ac9..."` and a string `punch_in`. | `ser_attendance` builds the exact contract shape; no `_id`; instants as epoch ms. |
| 15 | `list_attendance` (l.144-147) | `list(find(q))` loads every matching document and sorts and paginates in Python. At 100k records that is slow and memory-hungry. Sort is only by `date`, with no `emp_code` tie-break. | `GET /attendance` with no filters pulls the whole collection. | Sort, skip and limit in MongoDB (`date desc, emp_code asc`), backed by indexes; count with `count_documents`. |
| 16 | `list_attendance` (l.124-150) | Inputs not validated: any `status`, any date strings, `date_from > date_to` accepted, `page=0` slices with a negative index. Output leaks `_id` as `id`, returns datetimes, and does not default missing `history` / `half_day` on legacy documents. | `date_from=banana` returns 200. `page=0` returns a wrong slice. A legacy document comes back without `half_day` / `history`. | `Literal` status, strict `YYYY-MM-DD` validation, 422 for `date_from > date_to`, page bounds; `ser_attendance` applies the documented defaults and converts to ms. |
| 17 | whole file | No indexes are created, so every query is a collection scan and there is no uniqueness guarantee anywhere. | `db.attendance_logs.index_information()` shows only `_id_`. | `ensure_indexes()` runs at startup, is idempotent, and is retried from `/health` if the database was down at boot. |
| 18 | whole file | No handling of database errors, so a Mongo hiccup surfaces as a raw 500. | Stop MongoDB mid-request. | A `PyMongoError` handler returns 503 with a JSON body; duplicate keys are handled explicitly where they matter. |

## Looked at and decided it was fine

* `load_dotenv()` without `override=True`: real environment variables already win over `.env`, which is what the contract asks for.
* Endpoints are plain `def`, not `async def`: FastAPI runs them in a thread pool, so the blocking (thread-safe) PyMongo client does not block the event loop. I kept PyMongo rather than moving to an async driver.
* `doc.pop("_id", None)` after `insert_one`: needed, because `insert_one` mutates the dict by adding `_id`. The fix was to build the response separately so `_id` can never leak.
* `{"_id": 0}` projection in `list_employees`: correct.
* Defaults of `shift_start` / `shift_end` (`09:30` / `18:30`): match the contract.
* The helpers are reusable only in spirit: I rewrote all three because their signatures cannot express the attendance date (needed for overnight shifts and IST).
